# Phase 7 — 정상 운전 모드와 음악 명령 해석

2026-11-10, feature/voice-state, 개발자 A. 구현 전 해석표와 통합 경계.
기존 DrivingMode/MediaCommand/MediaController/DriverProfileRepository 공통 계약은 변경하지 않는다.

| 문장/문맥 | 해석 및 요청 |
|---|---|
| 오늘은 조용히 / 조용하게 운전할래 | 기존 콘텐츠 Stop 후 QUIET |
| 아니, 오늘은 조용하게 운전할래 | 이전 선호 제안 거절 + 명시적 QUIET 선택 |

| 발라드 틀어줘 / 신나는 음악 틀어줘 / 아이유 노래 틀어줘 | MUSIC + 명시적 query. 기존 취향보다 우선 |
| 노래 꺼줘 / 음악 중단 | Stop 후 QUIET. 위험/미확인 상태에서도 중단은 가능 |
| 다음 곡 | 현재 MUSIC일 때만 Next. 다른 모드이면 재확인 |
| 말동무 해줘 | 기존 콘텐츠 Stop 후 COMPANION 선택만. 대화/LLM/Gleo 호출 없음 |
| 이전 모드 제안에 “네” | 해당 모드 선택. 제안 없이 “네”만 말하면 미확인 |
| “발라드 좋아해” (음악 취향 질문 응답) | 발라드 query와 장르 선호 저장 요청 |
| “가수 아이유 좋아해” / “플레이리스트 출근 좋아해” (취향 질문 응답) | 구조가 명확한 가수/플레이리스트 취향만 반영 |
| 모호·상충·미지원·의문/가정·부정 명령 | 실행/저장 없이 짧은 재확인 안내 |

사전/전체 일치와 제한된 음악 요청 문형만 지원한다. 자유로운 한국어 전체 이해를 주장하지 않는다.
끝 마침표·느낌표, 공백 차이, 한글 NFC를 정규화한다. query에 부정/모드 전환이 섞이면 재확인한다.
음악 요청 query는 검색 의도이며 장기 취향으로 추정 저장하지 않는다. 취향 질문의 명시적 답변만 취향에 반영한다.

## 동작과 A/B 경계

- NORMAL + report=NORMAL + followUpRequired=false + restStopNeeded=false일 때만 일반 기능을 허용한다.
  초기 미확인/CAUTION/WARNING/HIGH_RISK/RESTING/RECOVERY_CHECK에서는 재생·질문·선호도 저장을 차단한다.
- 이전 모드는 먼저 제안하며 자동 실행하지 않는다. 저장된 장르/가수/플레이리스트는 MUSIC query 제안에 사용한다.
- 명시적 전환에서 현재 미디어 Stop 성공 후 새 재생을 요청한다. Stop 실패 시 새 콘텐츠를 겹쳐 요청하지 않는다.
- 재생 실패·시간 초과 시 자동 재생 재시도 없이 Stop을 추가 요청한다. 중단도 실패하면 모드를 미확정으로 표시한다.
  실제 서비스가 취소 이후 요청을 커밋하는 경합은 B가 직렬화/중단·상태 조회로 처리해야 한다.
- 모드 선택 성공 후에만 선호도 저장을 요청한다. 저장 실패는 재생 요청 성공과 별개로 표시한다.
- 취향 저장 시 최신 선택 프로필을 다시 읽고 해당 필드만 copy하여 좌석 외 A 모델의 기존 필드를 보존한다.
  원문 발화·건강 상태는 저장하지 않는다. 프로필이 없으면 일시적 선택은 가능하지만 저장하지 않는다.
- 프로필이 변경되면 이전 사용자의 대기 질문/재생을 취소한다. B는 savePreferences에서 선택 사용자 일치와
  동시 변경 충돌을 최종 검증해야 한다. 계약에는 원자적 버전/CAS 필드가 없어 A만으로 저장 경합을 보장할 수 없다.
- DriverStatus.mode를 수정하는 공통 메서드는 없으므로 A의 별도 모드 StateFlow를 제공한다.
  상태 관리자나 B UI를 임의 수정하지 않으며, 후속 ViewModel 통합에서 운전자 상태와 선택 모드를 함께 관찰한다.
- 실제 음악 검색/재생·뉴스 서비스·영구 저장은 B가 인터페이스 구현으로 담당한다. Fake만 테스트에 사용한다.
- 음악 취향 질문은 한 번만 수행한다. 침묵/오류/모호한 답변을 취향이나 졸음으로 추정하지 않는다.
  질문 30초/청취 10초/외부 미디어·저장 요청 15초 제한. 무한 재질문은 하지 않는다.

## 수명주기와 안전 우선

NormalDrivingCoordinator는 명시적 명령 또는 offerMode로만 동작하며 동일/역순 시각 명령을 무시한다.
observeChanges는 호출자 scope에서 실행하여 활동 중이 아닐 때도 위험/프로필 전환 시 콘텐츠 Stop을 요청한다.
활동 중에는 별도 guard도 모든 외부 대기 후 상태·사용자 일치를 확인하고, 바뀌면 이전 응답을 폐기한다.
위험 후 정상 복귀만으로 콘텐츠를 자동 재개하지 않는다. 다시 명시적 선택이 필요하다.
상위 소유자는 정상 대화를 cancel한 뒤 Phase 5 안전 경고를 실행해야 한다. 같은 VoiceService의 소유권을
다른 조정기와 동시에 갖지 않도록 실제 앱 조립에서 순서를 맞춘다. cancel/close는 음성 정리 완료를 기다린다.
Phase 8 말동무 실제 대화, Phase 9 타이머, 실제 UI/SDK 통합은 추가하지 않는다.
