# AI 음성 기반 운전자 상태 적응형 스마트 드라이빙 서비스

현재 서비스명: **쉼길** (기존 DriveMate). 명칭 변경이며 아래 기능 요구사항은 유지합니다.

**Pleos Connect 기반 운전자 안전 관리 및 개인화 주행 지원 애플리케이션**

- 문서 버전: 최종 기획안 v2.0
- 작성 기준: 2026년 11월 6일
- 개발 환경: Hyundai Motor Group Pleos Connect
- 수록 범위: 사용자 제공 최종 기획안 1~16장.

## 1. 서비스 개요

본 서비스는 운전자의 현재 신체 상태, 주행 시간, 개인 선호도를 종합적으로 활용하여 안전하고 편리한 운전 환경을 제공하는 음성 기반 스마트 드라이빙 애플리케이션이다.

차량 탑승 후 시동이 켜지면 애플리케이션이 활성화되어 운전자를 식별하고, 저장된 개인 프로필에 따라 차량 환경을 설정한다. 이후 TTS와 STT를 활용한 음성 질의응답으로 목적지와 운전자의 컨디션을 확인한다.

운전자의 상태가 정상일 경우 내비게이션과 함께 음악, 뉴스, 음성 대화 등의 개인화된 주행 환경을 제공한다. 반대로 피로 또는 졸음이 확인되면 위험 단계에 따라 차량 공조 및 환기 장치와 연계한 주의 환기, 추가 상태 확인, 휴식 장소 안내 등을 수행한다.

특히 본 서비스는 **목적지까지의 예상 주행 시간을 구간별로 분할하고, 각 구간에서 운전자 상태를 재확인하여 변화된 상태에 맞게 주행 모드를 자동으로 조정한다**는 점에서 기존 내비게이션과 차별화된다.

운전자 상태가 악화되거나 응답이 확인되지 않는 상황에서는 단계적으로 안전 조치를 강화하고, 운전자가 안전한 장소에서 휴식을 취하도록 지원한다.

단, 차량의 실제 정차·제어와 긴급 신고는 별도의 안전 시스템 및 공식 API 지원이 필요한 기능으로 구분한다.

## 2. 서비스 핵심 목표

1. **운전자 상태의 지속적인 확인:** 출발 시점뿐 아니라 주행 구간별로 운전자 상태를 갱신한다.
2. **상태 기반 적응형 주행 모드:** 정상, 피로, 고위험 상태에 따라 앱의 동작을 변경한다.
3. **단계별 위험 대응:** 피로 호소, 반복적인 졸음, 응답 부재 등 상황에 맞는 대응 체계를 제공한다.
4. **차량 기능과의 연동:** 공조, 창문, 좌석, 내비게이션 등 차량 기능을 활용한다.
5. **개인화된 운전 경험:** 운전자의 설정과 선호도를 저장하여 다음 주행에 반영한다.
6. **음성 중심 인터페이스:** 운전 중 화면 조작을 최소화한다.

## 3. 운전자 식별 및 개인 프로필 관리

### 3.1 차량 탑승 및 프로필 확인

차량 시동 시 앱이 자동 실행되는 것을 목표로 설계한다.

앱은 음성 안내를 통해 운전자의 이름 또는 프로필을 확인하고, 등록된 사용자 여부를 판단한다.

**기존 등록 사용자**

- 사용자 프로필 불러오기
- 기존 좌석 및 주행 환경 설정 확인
- 음악 및 콘텐츠 선호도 불러오기
- 직전 또는 자주 선택한 운전 모드 확인
- 개인화된 초기 질문 제공

**신규 사용자**

- 사용자 이름 입력 및 프로필 생성
- 운전자에게 적절한 좌석 위치 설정 안내
- 운전자가 직접 조정한 좌석 위치 및 등받이 각도 저장
- 이후 선택하는 음악·콘텐츠 선호도를 프로필에 반영

이름만을 이용한 식별은 동명이인이나 타인 사칭 가능성이 있으므로, 실제 서비스에서는 차량 프로필 선택 또는 별도 사용자 식별 수단과 결합하는 방식을 검토한다.

### 3.2 개인 프로필 저장 항목

| 분류 | 저장 정보 |
|---|---|
| 기본 정보 | 사용자 식별 정보, 이름 |
| 차량 설정 | 좌석 위치, 등받이 각도 |
| 음악 설정 | 선호 장르, 가수, 플레이리스트 |
| 주행 선호도 | 조용한 운전, 음악, 뉴스, 말동무 |
| 서비스 설정 | 음성 안내 선호도 |
| 최근 사용 기록 | 마지막으로 사용한 개인화 모드 |

**기술적 확인 사항**

Pleos의 기존 차량 프로필 시스템과 위의 모든 정보를 직접 연동할 수 있는지는 확인되지 않았다.

따라서 다음 두 가지 구현 방식을 검토한다.

- A안: Pleos 차량 프로필과 직접 연동
- B안: 앱 내부에 사용자별 프로필을 별도 저장하고, 지원되는 차량 설정만 연동

프로필 데이터는 필요한 정보만 저장하며, 운전자의 피로·건강 상태를 장기 보관할지는 개인정보 보호 측면에서 별도로 결정한다.

## 4. 목적지 설정 및 초기 컨디션 확인

프로필 확인 후 앱은 목적지를 질문한다.

**음성 질의응답 예시**

앱: "오늘은 어디로 이동하시나요?"

운전자: "서울역으로 가줘."

앱: "서울역으로 안내하겠습니다. 현재 몸 상태는 어떠신가요? 졸리거나 피곤하지는 않으신가요?"

운전자의 음성을 STT로 변환하고 앱 내부 상태 분석 로직을 통해 운전 상태를 분류한다.

| 운전자 응답 | 상태 분류 | 앱 동작 |
|---|---|---|
| "괜찮아", "안 졸려" | 정상 | 일반 운전 모드 |
| "조금 피곤해", "좀 졸려" | 주의 | 1차 위험 대응 |
| "너무 졸려", "운전 못 하겠어" | 고위험 | 즉시 휴식 장소 안내 및 정차 권고 |
| 응답 없음 | 미확인 | 재확인 및 단계적 경고 |

응답 내용만으로 실제 졸음 여부를 확정하지 않으며, 위험 가능성을 감지하여 적절한 안전 행동을 권고하는 용도로 활용한다.

## 5. 일반 운전 모드 및 개인화 기능

운전자가 정상 상태라고 응답하면 내비게이션 안내를 시작한다.

이후 개인 프로필에 저장된 이전 선택을 활용하여 운전 중 원하는 콘텐츠를 제공한다.

### 5.1 일반 운전 모드 선택지

**① 조용한 운전**

- 내비게이션 안내만 제공
- 불필요한 대화 및 미디어 재생 최소화
- 주행 구간별 상태 확인 및 필수 안전 안내는 유지

**② 음악 재생**

- 선호하는 장르와 가수에 따른 음악 추천
- 연결된 음악 서비스에서 곡 검색 및 재생
- 과거 재생 이력을 활용한 개인화
- 주행 중 음성으로 노래 변경 및 재생 중단

**③ 간단한 음성 말동무**

- 운전자가 혼자 장시간 운전할 때 짧은 음성 상호작용 제공
- 사용자 요청에 따른 간단한 대화
- 운전과 관련한 가벼운 질문이나 일상 대화
- 안전 안내가 필요할 경우 일반 대화 중단

본 기능은 Gleo AI의 자유로운 대화 및 앱 연동 범위에 따라 개발 가능 여부가 달라진다.

**④ 뉴스 및 오디오 콘텐츠**

- 연결된 콘텐츠 서비스의 뉴스 또는 오디오 재생
- 사용자의 콘텐츠 선호도 저장
- 음성 명령에 따른 재생과 중단

### 5.2 프로필 기반 질문 개인화

최초 이용 시 사용자가 음악 재생을 선택했다면 해당 설정을 프로필에 저장한다.

**최초 이용**

앱: "조용한 운전, 음악, 뉴스, 말동무 중 무엇을 원하시나요?"

운전자: "음악 틀어줘."

앱: "어떤 음악을 좋아하시나요?"

운전자: "발라드 좋아해."

지원 가능한 음악 서비스에서 곡을 검색해 재생하고, 선호도를 기록한다.

**다음 이용**

앱: "오늘도 발라드를 들으면서 운전하시겠어요?"

운전자: "아니, 오늘은 조용하게 운전할래."

앱: "알겠습니다. 조용한 운전 모드로 변경하겠습니다."

이처럼 이전 설정을 활용하여 반복 질문을 줄이면서 운전자에게 선택권을 제공한다.

### 5.3 음악 재생 기술 검토

음악 재생 방식은 다음과 같이 구분한다.

- 차량에 설치된 음악 앱과 연동하여 검색 및 재생
- 연결된 스트리밍 서비스의 음악 재생
- 차량에 저장된 로컬 음악 파일 재생
- 휴대전화에 연결된 음악 서비스 제어

Gleo AI가 특정 음악 앱의 곡 검색 및 재생을 지원하는 사례는 공식 문서에 있으나, 개발 중인 제3자 앱이 다른 음악 앱 또는 휴대전화를 자유롭게 제어할 수 있는지는 확인이 필요하다.

또한 자연어로 음악 취향을 분석하고 적합한 음악을 검색하는 기능은 Gleo AI의 제공 범위와 음악 서비스 연동 방식에 따라 구현 수준이 달라진다.

## 6. 주행 시간 기반 운전자 상태 모니터링

### 6.1 핵심 기능

목적지 설정 후 내비게이션에서 예상 주행 소요 시간을 받아 전체 주행 시간을 여러 구간으로 분할한다.

각 구간의 시작 시점에 운전자에게 현재 상태를 질문하여 운전자 상태 정보를 갱신한다.

**예상 주행 시간 60분, 3구간 적용 예시**

| 시점 | 기능 |
|---|---|
| 출발 | 초기 운전자 상태 확인 |
| 약 20분 후 | 2차 상태 확인 |
| 약 40분 후 | 3차 상태 확인 |
| 목적지 도착 | 주행 종료 |

실제 질문 주기는 목적지까지 남은 시간, 주행 시간, 이전 운전자 상태 등을 고려하여 조정한다.

예를 들어 120분 주행 시 구간을 4개로 나누어 약 30분 간격으로 확인할 수 있다.

단, 일반 주행 구간별 질문과 위험 감지 이후의 추가 질문은 별도 주기로 관리한다.

### 6.2 상태 정보 갱신

운전자의 답변이 수신되면 다음 항목을 갱신한다.

- 현재 운전자 상태: 정상 / 피로 / 고위험 / 미확인
- 마지막 상태 확인 시점
- 직전 상태와의 변화 여부
- 추가 확인이 필요한지 여부
- 현재 적용 중인 주행 모드

이를 통해 최초 정상 상태였던 운전자가 주행 중 피로를 느끼는 경우에도 위험 대응 모드로 전환할 수 있다.

## 7. 피로 및 졸음 감지 시 단계별 대응

### 7.1 1차 위험 대응: 피로 및 가벼운 졸음

운전자가 "조금 피곤해", "졸려" 등의 답변을 하면 주의 운전 모드로 전환한다.

**1차 조치**

1. 운전자에게 피로 상태를 인지했음을 음성으로 안내한다.
2. 안전한 장소에서 휴식할 것을 권고한다.
3. 설정에 동의한 운전자에게 공조 온도 조절 또는 환기를 제안한다.
4. 지원되는 차량 기능에 한해 에어컨 온도 조절 또는 창문 열기 기능을 실행한다.
5. 변경 전 공조 및 창문 상태를 저장한다.
6. 일정 시간 후 상태를 다시 확인한다.

공조·환기 조절은 졸음을 해소하는 확실한 수단이 아니라 일시적인 주의 환기 보조 기능으로 사용한다.

**예시**

앱: "피곤하신 것 같네요. 안전한 곳에서 잠시 휴식하시는 것을 권장합니다. 환기를 도와드릴까요?"

운전자: "응."

앱: "창문을 조금 열어 환기하겠습니다."

### 7.2 1차 조치 이후 재확인

운전자의 상태에 따라 잠시 후 추가 질문을 진행한다.

초기 기획에서는 약 5~10분을 재확인 시간으로 고려하되, 실제 운전자의 졸음이 확인된 상황에서는 시간을 채울 때까지 운전을 계속하도록 유도하지 않는다.

운전자가 즉시 쉬고 싶다고 하거나 졸음이 심해지면 지체 없이 휴식 장소 안내로 전환한다.

**상태가 회복되었다고 응답한 경우**

앱: "현재 상태는 좀 나아지셨나요?"

운전자: "이제 괜찮아."

앱: "알겠습니다. 잠시 후 상태를 다시 확인하겠습니다."

이후 짧은 간격으로 한 차례 추가 확인한다.

상태가 안정적이고 운전자가 원할 경우 변경했던 공조 및 창문 설정을 복원하고 일반 운전 모드로 전환한다.

**여전히 졸리다고 응답한 경우**

앱: "졸음이 계속되고 있습니다. 가까운 안전한 정차 장소를 안내하겠습니다."

- 주변 휴게소 및 졸음쉼터 탐색
- 가장 가까운 안전한 정차 후보 제시
- 운전자 확인 후 경유지 설정
- 안전한 장소에 정차하여 휴식을 취하도록 권고

### 7.3 운전자가 차량 설정을 수동 변경하는 경우

1차 조치 후 운전자가 에어컨을 끄거나 창문을 닫는 경우, 지원되는 차량 상태 조회 기능을 통해 변경 여부를 감지한다.

단, 운전자의 수동 조작을 위험 상태의 증거로 단정하지 않는다.

앱은 추가 상태 확인을 제공할 수 있다.

앱: "환기 설정이 변경되었습니다. 현재 상태는 좀 나아지셨나요?"

운전자: "응, 이제 괜찮아."

앱: "알겠습니다. 잠시 후 다시 확인하겠습니다."

또는

운전자: "아니, 여전히 졸려."

앱: "가까운 휴식 장소를 안내하겠습니다."

운전자가 수동으로 변경한 차량 설정은 존중하며, 앱이 반복적으로 원래 조치를 강제로 재적용하지 않도록 설계한다.

---

## 8. 2차 위험 대응: 질문 무응답 및 심한 졸음 의심

### 8.1 무응답 감지

상태 확인 질문 이후 일정 시간 동안 답변이 없을 경우 무응답 상태로 처리한다.

단, STT 인식 실패, 주변 소음, 통신 문제 등으로도 무응답이 발생할 수 있으므로 무응답 자체를 졸음의 확정 증거로 사용하지 않는다.

### 8.2 1차 무응답 발생

- 질문 재전달
- 음성 경고 제공
- 경고음 또는 지원되는 알림 방식 활용
- 안전한 장소에 정차하도록 권고
- 응답 수신 여부 재확인

**예시**

앱: "운전자 상태가 확인되지 않습니다. 괜찮으신가요? 가능하면 안전한 곳에 정차해 주세요."

### 8.3 2차 무응답 발생

반복적으로 응답이 확인되지 않으면 고위험 의심 상태로 전환한다.

- 안전 관련 경고 강화
- 현재 진행 중인 음악 또는 일반 음성 대화 중단
- 가까운 정차 가능 장소 탐색
- 휴식 장소 안내 우선 제공
- 응답 및 차량 상태 확인 지속

주행 중 시트 위치나 등받이 각도를 강제로 변경하는 기능은 조향 및 페달 조작에 위험을 줄 수 있으므로 적용하지 않는다.

운전자가 다시 응답하면 현재 상태를 확인하고, 졸음이나 운전 곤란을 호소하는 경우 휴식 안내를 최우선으로 수행한다.

### 8.4 지속적인 무응답과 긴급 상황

2차 경고에도 응답하지 않는 상황은 별도 고위험 대응 시나리오로 분류한다.

추가 검토 기능은 다음과 같다.

- 차량 자체 긴급 안전 기능과의 연동
- 사전 등록한 비상 연락처에 상태 알림
- 긴급 지원 서비스 이용 안내
- 실제 응급상황이 확인된 경우 신고 지원

**119 자동 신고는 추가 검토 기능으로 분리한다.**

음성 무응답만으로 자동 신고하면 오신고가 발생할 수 있고, 신고 기능은 별도의 서비스 제공 여부, 기술 연동, 동의 및 법적 검토가 필요하다.

따라서 단순 무응답 횟수만으로 119에 자동 신고하는 기능은 확정 기능에 포함하지 않는다.

## 9. 휴식 장소 안내 및 휴식 지원

### 9.1 휴식 장소 검색

운전자가 반복적으로 졸음을 호소하거나 운전하기 어렵다고 응답한 경우 주변에서 안전하게 정차할 수 있는 장소를 탐색한다.

검색 대상은 다음과 같다.

- 고속도로 휴게소
- 졸음쉼터
- 일반 도로 주변의 주차 가능한 시설
- 안전한 정차가 가능한 기타 장소

실제 검색 결과는 도로 유형, 진행 방향, 접근 가능 여부를 반영해야 한다.

### 9.2 내비게이션 연동

검색된 휴식 장소를 사용자에게 안내하고 경유지 설정을 지원한다.

예시:

"현재 상태를 고려하면 휴식이 필요합니다. 가까운 휴식 장소로 안내할까요?"

사용자가 동의하면 기존 목적지에 휴식 장소를 경유지로 추가한다.

차량의 실제 제동, 조향 및 강제 정차 기능은 본 앱의 기능 범위에 포함하지 않는다.

### 9.3 정차 후 휴식 타이머

운전자가 안전한 장소에 정차하고 휴식을 시작하면 TTS를 통해 휴식 시간을 질문한다.

**예시**

앱: "안전하게 정차하셨습니다. 몇 분 동안 휴식하시겠어요?"

운전자: "20분."

앱: "20분 후 알람을 설정하겠습니다. 편안히 쉬세요."

주요 기능은 다음과 같다.

- 음성으로 휴식 시간 설정
- 휴식 타이머 및 알람 실행
- 알람 연장 및 해제
- 휴식 종료 후 운전자 상태 재확인
- 정상 상태 확인 후 기존 목적지 안내 재개

휴식 타이머가 종료되더라도 자동으로 주행을 재개하거나 운전이 가능한 상태라고 판단하지 않는다.

## 10. 위험 구간 진입 시 안전 안내

일반 모드와 주의 운전 모드 모두에서 도로상 위험 구간에 대한 안전 안내를 제공한다.

대상 구간은 다음과 같다.

- 어린이보호구역
- 사고 다발 구간
- 속도 단속 구간
- 급커브 및 기타 위험 도로 구간

**안내 예시**

"어린이보호구역에 진입합니다. 보행자와 제한속도에 주의해 주세요."

"전방 사고 다발 구간입니다. 안전거리를 유지해 주세요."

위험 구간에서는 불필요한 질의응답을 추가하기보다 간결한 음성 안내를 우선하며, 내비게이션의 기존 안전 알림과 중복되지 않도록 조정한다.

## 11. 전체 서비스 동작 시나리오

**단계 1. 차량 탑승 및 시동**

차량 시동 후 앱 활성화 → 사용자 식별 → 프로필 확인

**단계 2. 사용자 프로필 설정**

신규 사용자: 프로필 생성 및 좌석 설정 안내

기존 사용자: 저장된 정보 불러오기

**단계 3. 주행 초기 설정**

목적지 입력 → 운전자 컨디션 확인 → 주행 모드 결정

**단계 4. 정상 운전**

내비게이션 실행 → 기존 선호 콘텐츠 제안 → 주행 구간별 상태 확인

**단계 5. 피로 감지**

주의 운전 모드 전환 → 휴식 권고 → 동의한 공조·환기 보조 조치 → 추가 상태 확인

**단계 6. 상태별 분기**

- 회복 응답: 추가 확인 후 기존 설정 복원
- 피로 지속: 휴식 장소 안내
- 심한 졸음: 즉시 휴식 장소 안내
- 무응답: 단계적 경고 및 고위험 대응

**단계 7. 휴식**

안전한 정차 → 휴식 시간 설정 → 알람 제공 → 운전자 상태 확인

**단계 8. 주행 재개**

운전자 선택 및 상태 확인 → 기존 목적지 안내 재개 → 상태 모니터링 유지

## 12. 핵심 시스템 구성

### 12.1 음성 인터페이스

- Pleos TTS: 질문, 안내, 경고 및 알람 음성 출력
- Pleos STT: 사용자의 음성 응답을 텍스트로 변환
- 앱 내부 로직: 답변 분류, 질문 결정, 상태 갱신 및 모드 전환
- Gleo AI: 자연어 이해, 음성 기능 호출 및 대화형 기능 지원 가능성 검토

### 12.2 운전자 상태 관리

앱 내부에 다음과 같은 상태를 관리하는 State Machine을 구현한다.

- NORMAL: 정상 운전
- CAUTION: 피로 및 가벼운 졸음
- WARNING: 피로 지속 또는 반복 경고
- HIGH_RISK: 심한 졸음 또는 지속 무응답 의심
- RESTING: 휴식 중
- RECOVERY_CHECK: 휴식 후 또는 상태 회복 재확인

### 12.3 차량 및 내비게이션 연동

- Seat API: 좌석 상태 조회와 지원되는 설정 관리
- HVAC API: 공조 상태 조회 및 온도 변경
- Window API: 창문 상태 조회 및 제어
- NaviHelper API: 목적지 설정과 휴식 경유지 연동
- 위치 및 주행 정보 API: 주행 상황에 따른 상태 확인 및 장소 안내

각 API는 실제 지원 여부와 권한을 확인한 이후 사용한다.

## 15. 서비스 차별화 및 기대 효과

**① 단발성 경고가 아닌 지속적인 운전자 상태 관리**

운전 시작 시 한 번만 상태를 확인하는 것이 아니라 예상 주행 시간을 나누어 주기적으로 상태를 갱신한다.

**② 운전자 상태 변화에 따른 실시간 대응**

운전자의 피로, 졸음 및 응답 변화에 따라 일반 모드에서 위험 방지 모드로 전환한다.

**③ 차량 제어 기능을 활용한 안전 지원**

공조 및 환기 기능과 내비게이션을 연결하여 단순 경고를 넘어 안전한 휴식을 유도한다.

**④ 사용자별로 달라지는 개인화 경험**

선호하는 음악, 콘텐츠 및 운전 방식을 저장하여 다음 주행에 반영하고 불필요한 질문을 줄인다.

**⑤ 휴식 전후를 연결하는 운전 지원 서비스**

위험 감지 → 휴식 장소 안내 → 휴식 타이머 → 상태 재확인 → 주행 재개까지 하나의 흐름으로 지원한다.

## 16. 최종 서비스 방향

본 서비스는 단순한 내비게이션 앱이나 졸음 경고 앱이 아닌, **운전자의 상태를 지속적으로 확인하고 그에 맞춰 차량 환경과 운전 지원 서비스를 변화시키는 음성 기반 적응형 드라이빙 서비스**를 지향한다.

핵심 기능인 상태 확인과 위험 대응을 우선 구현하고, Gleo AI 및 음악·개인화 관련 기능은 Pleos 플랫폼의 실제 지원 범위를 확인하면서 확장한다.

안전과 직접 관련된 기능은 운전자의 선택권과 차량 제어 제한을 존중하며, 주행 중 불필요한 조작과 상호작용을 최소화하는 방향으로 개발한다.

## 구현 시 적용할 저장소 안전 제약

아래는 원문과 구분되는 `AGENTS.md`의 구현 제약이다.

- 조향·제동 제어, 주행 중 좌석 이동, 무응답만을 근거로 한 자동 긴급 신고를 구현하지 않는다.
- 경로 변경과 공조·창문 변경에는 운전자 동의를 유지하고 수동 설정 변경을 존중한다.
- STT 무응답이나 실패를 졸음의 확정 증거로 취급하지 않는다.
- 실제 Pleos SDK 연동과 Mock 동작을 코드와 문서에서 구분한다. 위 서비스 목표는 실제 SDK 지원이나 구현 완료를 의미하지 않는다.
- 외부 생성형 AI API는 명시적인 추가 요구 없이 도입하지 않는다.
