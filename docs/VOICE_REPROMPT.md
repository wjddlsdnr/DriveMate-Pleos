# 음성 재질문 수정

## 흐름과 경계

- 기존 모드 제안 → TTS 성공 완료 → STT 최종 결과 → 명시적 선택 실행.
- 이전 모드 거절(아니요) 또는 모호한 명령 → 선택지 재질문 → TTS 성공 완료 → STT.
- 추가 재질문은 작업당 한 번. 다시 모호하면 종료 안내 후 CLARIFY로 끝내며 재생/저장하지 않는다.
- 음악 선택 후 취향 질문은 기존 정책을 유지한다. 재질문 예산은 취향/모드 흐름에서 공유한다.
- TTS 실패 시 청취하지 않으며 무응답/권한/서비스 오류는 기존 실패 처리로 전달한다.
- 기존 action/watcher/VoiceService를 사용해 안전 선점, 프로필 변경, 취소 시 정리한다.

## 상태 질문 문맥

공통 DriverStateManager/VoiceService 계약은 변경하지 않는다. A의 질문 경계에서만
단순 긍정/부정을 명시적인 상태 표현으로 의미 해석한 뒤 기존 관리기로 전달한다.
이는 STT 결과를 만들어내는 것이 아니라 최종 Text 응답에 대한 결정적 해석이다.
STT 오류/무응답/시간 초과/권한 거부는 그대로 전달한다.

| 질문 문맥 | 예/네/응 | 아니/아니요 |
|---|---|---|
| 현재 졸리거나 피곤하신가요? | 가벼운 피로 보고 | 정상 보고 |
| 현재 괜찮으신가요? | 정상 보고 | 미확인(심각도 판단 불가) |
| 문맥 없음/복합 질문 | 미확인 | 미확인 |

회복 질문도 ‘현재 졸리거나 피곤하신가요?’로 통일한다. 정상 보고가 들어와도 기존 회복
상태 머신의 재확인/정차/명시적 재개 동의 조건은 유지한다.
‘안 졸림’, ‘졸리지 않음’, ‘안 피곤함’은 정상 표현으로 추가한다.
상충·이중 부정·알 수 없는 문장은 미확인으로 유지한다.

## 검증 계획

Fake로 거절→재질문→로컬 명령, 반복 모호함의 상한, TTS/STT 순서, 실패와 위험/취소를 확인한다.
가상 시간 기반 기존 회귀 테스트와 debug 빌드/lint를 실행한다.
실제 Emulator 결과는 별도 검증 문서에 기록하며 Fake 통과를 실제 발화 성공으로 표시하지 않는다.
B UI/차량/내비/외부 콘텐츠와 SDK 버전은 변경하지 않는다.
초기 검증 중에는 커밋/푸시하지 않았으며, 2026-11-13 사용자의 별도 요청에 따라
검토·검증 후 feature/voice-state로 커밋·푸시해 B에게 인계한다.
