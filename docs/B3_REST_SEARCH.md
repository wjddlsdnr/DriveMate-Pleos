# B3 후속: 실제 휴식 장소 검색 준비

구현 후속: [B3 휴게소 데이터·TMAP 검색 어댑터](B3_PLACE_DATA.md). PC 전용 도로공사 카탈로그 처리와 TMAP 검색 요청/응답 경계를 구현했다. 도로공사 203건을 읽었고 TMAP 정상 인증은 남아 있다. 앱의 자동 안전 검색이 완성된 상태는 아니다.

후속 현황: 사용자가 TMAP AppKey와 data.ex.co.kr 인증키를 발급받았다. [로컬 키 설정/연결 확인 도구](B3_API_KEYS.md)를 추가했다. 아래 계정 미보유 설명은 최초 조사 시점 기록이다. 실제 인증·안전 검색 연결 완료를 뜻하지 않는다.

확인일: 2026-11-11. 사용자 보유 API 계정·키는 없으며 후보 조사부터 진행한다. 이 문서는 연결 후보와 구현 의존성을 기록한다. 서비스 계정을 만들거나 유료 상품을 신청하지 않았고 외부 HTTP 검색 구현·호출은 추가하지 않았다.

## 연결 후보와 제안

첫 검증 후보는 **TMAP 장소/경로 검색 + 한국도로공사 휴게소 기준정보** 조합이다. 이는 조사에 따른 구현 제안이며, 두 서비스만으로 안전 판정이 보장된다는 의미가 아니다. 초기 지원 범위는 고속도로 휴게소로 제한하고 졸음쉼터·일반도로 주차장은 별도 근거가 확보된 뒤 확장하는 편이 적절하다.

- [TMAP 공식 기능 목록](https://openapi.sk.com/products/preview/tmap?menuSeq=4&svcSeq=4)은 장소 검색, 주변 카테고리 검색, 경로 반경 검색 및 자동차 경로 안내를 제공한다. [장소 상세 API](https://openapi.sk.com/products/detail?linkMenuSeq=13)는 appKey가 필요하고 위치·업종·시설 정보를 조회한다. 장소와 경로를 함께 검증할 후보지만, 공개 기능 목록만으로 Pleos의 실제 안내 경로와 일치하거나 합법적 주차를 보증한다고 판단하지 않는다. 상품별 사용 조건·가격·데이터 저장/재배포·차량 앱 이용 조건은 신청 전 확인해야 한다.
- [한국도로공사 휴게소 기준정보](https://www.data.go.kr/data/15076770/openapi.do)는 위치·노선·운영 방향 정보를 제공하는 후보다. 고속도로 시설·방향 보조 근거에 적합하지만 현재 운영/진입 제한·주차 가용성은 별도 확인 대상이다. [공식 가이드](https://data.ex.co.kr/guidedown/openoasis_guide.pdf)의 검색 색인에서 인증키 필요를 확인했으나 PDF 본문 가져오기는 시간 초과했다. 실제 endpoint·응답 필드·단위는 아직 대조하지 못했으므로 클라이언트를 추정 구현하지 않는다.
- [Kakao Local](https://developers.kakao.com/docs/en/local/dev-guide)은 REST API 키로 장소·좌표와 주차장(PK6) 카테고리를 조회한다. 일반도로 장소 발견의 후속 후보다. 문서의 장소 응답만으로 현재 경로의 진입 방향·합법적 휴식 주차·운영 상태를 확정할 수 없어 단독 안전 검색 공급자로 연결하지 않는다.

## 키 이외에 먼저 필요한 것

현재 공통 RestStopSearch는 검색 ID·경로 ID·revision만 전달한다. RouteProgress에는 ETA가 있지만 위치·도로·방향·경로 형상이 없다. 따라서 이름이나 직선거리만으로 후보를 고르지 않는다. B 소유 내비/위치 어댑터가 실제 안내 경로와 같은 revision에 묶인 현재 위치·방향·도로/경로 근거를 제공할 수 있는지 SDK와 권한부터 확인해야 한다. 필요하면 B 내부 snapshot으로 공급하고 A 계약 변경은 별도 영향 설명 후 협의한다.

TMAP POI ID를 Pleos POI ID로 임의 변환하거나 복사하지 않는다. 공급자 식별자가 다른 경우 좌표 전달 방식과 Pleos에서 확인한 경로 결과를 대조해야 한다. 지도 서비스의 별도 계산 경로가 Pleos 실제 경로와 다를 수 있으므로 TMAP 경로만 보고 진행 방향 일치를 true로 지정하지 않는다.

외부 검색에는 차량 위치·목적지 전송이 수반될 수 있다. 연동 전 전송 범위와 사용자 동의, 키 보호 방식을 정해야 한다. 운영용 비밀키를 APK나 저장소에 넣지 않으며 필요하면 서버 중계 구조를 선택한다. 계정 없이 동작하는 임의 키·가상 장소·고정 성공 응답은 넣지 않는다.

## 이번 코드 보강

- VerifiedRestStopFinder: 기본 8초 검색 제한. 시간 초과/권한 거부/서비스 오류를 기존 FailureReason으로 구분하고 상위 작업 취소는 전파한다.
- 결과 또는 오류가 도착할 때 경로 ID/revision을 다시 검사해 이전 경로의 실패가 새 경로에 적용되지 않게 한다.
- 안전 근거가 모두 있는 유효 좌표만 반환하며 같은 좌표의 후보를 중복 제거하고 최대 5개로 제한한다. 공급자가 준 순서를 유지하며 안전성이나 거리 순위를 새로 추정하지 않는다.
- DriveMateAppGraph: 내비와 휴식 검색 포트를 반드시 함께 교체하도록 강제한다. 실제 내비만 주입하고 검색은 기본 Fake로 남기는 구성을 생성 시 거부한다.
- A 코드·공통 계약·SDK/Gradle 버전·Manifest·화면 변경 없음. 운영 RestStopDataSource는 여전히 미연결이며 UNSUPPORTED다.

## 후속 구현 순서

1. TMAP 및 도로공사 서비스 가입/상품 이용 조건과 키 발급 방법 확인. 계정/결제/약관 동의는 사용자가 수행한다.
2. 실제 SDK에서 위치·방향·경로 근거 확보 가능성 확인. 불가하면 자동 후보 제안 범위를 다시 정하고 미확인 후보를 안전 후보로 반환하지 않는다.
3. 승인된 테스트 계정으로 실제 응답 샘플·오류·단위를 대조한 후 B 내부 HTTP gateway와 데이터 모델을 구현한다.
4. 방향·진입 가능·주차 근거의 출처/시각/유효기간과 공급자 간 ID 매칭을 검증한다. 근거 부족은 후보 제외 또는 UNSUPPORTED다.
5. 검색→후보 안내→별도 동의→경유지 요청→실제 콜백 확인을 검증한다. 실제 경로 변경은 사용자 확인 없이 자동 테스트하지 않는다.

검증 결과는 B3_NAVIGATION.md의 2026-11-11 후속 항목에 기록한다. 실제 외부 검색, 신규 화면 계측 및 실차 검증은 이번에 수행하지 않았다.
