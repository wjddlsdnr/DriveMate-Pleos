# 주변 검색의 위치 전송 동의 경계 — 2026-11-14

## 이번 범위

B 내부 NearbySearchConsentGate와 PC TMAP 주변 검색 URI 생성기를 추가했다.
아직 UI/Android HTTP/중계의 위치 요청 엔드포인트는 연결하지 않았다.
기존 일반 discovery 엔드포인트는 위치·본문을 계속 거부한다.
이 단계만으로 실제 주변 검색이나 안전 후보 검색을 완료했다고 표시하지 않는다.

## 동의 흐름

1. UI가 최신 RestSearchContext로 prepare를 호출한다.
2. TMAP에 중계를 통해 현재 위도·경도를 보내 주변 휴식 장소를 발견한다는 목적과 수신자를 표시한다.
   heading/native ID/프로필/음성 원문은 전송 범위가 아니다.
3. 사용자가 명시적으로 동의한 UI 이벤트에서만 confirmFromUi를 호출한다.
4. HTTP 직전에 같은 경로·revision·좌표·측위 수신 시각의 문맥으로 consume한다.
5. 반환 Request는 좌표와 고정 5km 반경만 제공한다. 토큰은 한 번 소비하면 다시 사용할 수 없다.

위치 문맥 수명 5초 내에서만 동의가 유효하다. 새 위치 수신이나 경로 revision 갱신으로
문맥이 달라지면 재확인이 필요하다. 현재는 안전 경계를 우선한 순수 로직이며,
실제 화면의 동의 시간·위치 갱신 UX는 별도 검증이 필요하다.
prepare의 Offer ID를 조작하거나 Permit을 복제해도 저장된 허용 객체와 동일하지 않으면 거부한다.
취소/배경/사용자 전환 시 조립 지점은 cancel을 호출해야 한다. 아직 해당 UI 수명주기에 주입하지 않았다.
공통 계약·경로 변경 동의·A 음성 판단은 변경하지 않는다.

## 주변 요청 형식

기존 공식 POI 검색 endpoint에 searchtypCd=R, centerLat, centerLon, radius를 추가한다.
HTTPS 고정 호스트, 일반 휴게소 검색어, WGS84GEO, 20개 첫 페이지를 유지한다.
반경은 생성기에서 1~10km로 제한하며 앱 요청은 5km 고정이다.
현재 좌표값을 실제로 전달하는 함수는 연결하지 않았고 합성 좌표로만 URI 형식을 검사했다.
키를 URL에 추가하지 않는다. 문화권에 관계없이 소수점은 점으로 직렬화한다.
근거: https://tmap-skopenapi.readme.io/reference/장소통합검색

- 빌드·전체 단위 결과는 후속 기록 참조. Emulator/UI 동의/실제 주변 검색 미실행.
- 기존 음성·위치·중계 변경과 미추적 파일 보존. 커밋·푸시하지 않았다.
