# 개발자 A/B 경계와 공통 계약 제안

상태: Phase 1 합의용 초안. B의 검토·합의는 아직 받지 않았다. 공통 타입이 필요한 이유는 A가 SDK를 직접 호출하지 않고 판단 결과를 B에게 전달하기 위해서다. 영향 범위는 아래 새 `contract/` 파일 및 향후 구현체이며 기존 UI/SDK 호출에는 영향이 없다.

## 파일 및 패키지 소유권

아래 경로는 `app/src/main/java/com/example/pleosconnect/` 기준이다. `contract/` 외 새 패키지는 계획이며 빈 디렉터리를 미리 만들지 않았다.

| 영역 | 담당 | 책임 |
|---|---|---|
| `contract/model`, `contract/integration` | A/B 공동 검토 | 앱 데이터·요청·결과 모델과 B 구현 포트 |
| `contract/voice`, `contract/logic` | A 제안, B 소비 계약 검토 | 대화/상태/질문 API, UI가 관찰할 상태 |
| `domain/`, `voice/`, `scheduler/` | A | 응답 분석·상태 전이·대화·음성 명령·주기·휴식 타이머 |
| `pleos/voice/`, `mock/voice/` | A | 실제 STT/TTS 또는 명시된 Mock. Gleo 검토는 별도 A 영역 |
| `MainActivity.kt`, `ui/`, `res/` | B | 화면/디자인/Compose 및 ViewModel UI 연결 |
| `data/profile/` | B | 사용자 식별·프로필·음악/콘텐츠 선호도 저장, 좌석 데이터 |
| `pleos/navigation/`, `pleos/vehicle/` | B | NaviHelper, 휴식 POI, HVAC/Window/Seat 및 수동 변경 감지 |
| `data/media/`, `mock/integration/` | B | 실제 음악/뉴스 연동 및 B 포트의 Mock |
| Gradle, Manifest, 앱 조립 지점 | 변경 사유 사전 공유 | A 음성 의존성/권한, B 차량/콘텐츠/앱 카테고리 설정 충돌 방지 |

현재 B 구현 파일은 없으며 기존 기본 UI는 변경하지 않았다. 이 작업은 다른 브랜치의 구현 유무를 추정하지 않는다. 기존 `feature/voice-state`에서만 작업하고 main/develop 직접 push 또는 merge는 하지 않는다.

## 인터페이스별 구현 담당

| 인터페이스 | 구현 담당 | 입력/출력 |
|---|---|---|
| VoiceService | A | 질문 → 재생 완료, 청취 → 텍스트 또는 구별된 실패 |
| DriverStateManager | A | 상태 질문 답변 → 상태/확인 시점/후속 확인 필요 |
| CheckScheduler | A | 경로 개정/위험 확인 요청 → 중복 제거된 기한 도래 질문 |
| ConversationController | A | 대화 시작/상태 확인/중단 → 관찰 가능한 대화 단계 |
| NavigationController | B | 동의된 목적지/경유지/재개 요청 → 성공/실패 및 경로/ETA |
| RestStopFinder | B | 현재 경로 기준 검색 → 접근 가능한 휴식 후보 또는 실패 |
| MediaController | B | A가 해석한 재생/중단/다음 곡/뉴스 명령 → 성공/실패 |
| VehicleController | B | 공조/환기 제안 → 동의 후 실행/복원. 원래 설정은 B가 보관 |
| DriverProfileRepository | B | 선택된 사용자 선호도 제공, A가 얻은 선호도 저장 요청 |

프로필은 A에 필요한 투영 모델만 제공한다. 좌석 값의 단위·범위·식별 방법을 SDK 확인 없이 공통 모델로 추정하지 않았다. B가 관리하는 좌석/차량 프로필 구조를 대체하지 않는다. 좌석 동작·조향·제동·긴급 신고는 이 계약에 노출하지 않는다.

## 연계 흐름과 안전 조건

1. B가 선택된 프로필과 활성 경로/ETA를 제공한다. A가 질문/모드를 결정한다.
2. A가 위험을 판단하면 일반 콘텐츠 중단을 요청하고 휴식을 권고한다. 검색은 RestStopFinder로 B에게 요청한다.
3. B의 후보를 안내한 뒤 A가 명시적 동의를 획득해 후보/검색·경로 개정과 함께 경유지 요청한다. 오래된 경로/검색 결과는 B가 거부한다.
4. 차량 보조는 B의 지원 가능한 제안을 음성으로 알린 뒤 동의를 받는다. B는 변경 전 설정을 보관하고 수동 변경을 존중한다. 복원은 별도 동의와 유효성 검증이 필요하다.
5. 빈 검색 결과, 미지원, 권한 거부, 서비스 실패를 성공으로 취급하지 않는다. 운전자에게 제한을 알리고 안전한 정차를 권고한다.
6. 실제 구현과 Mock은 구현 클래스/설정/문서에서 명시한다. 공통 인터페이스를 구현했다는 사실은 SDK 지원이나 차량 동작을 입증하지 않는다.

## 합의가 필요한 항목

- 제안/동의 ID 생성 주체, 유효 시간, 철회·일회성 소비 방법과 오류 매핑
- 프로필 변경 경쟁 처리와 사용자 전환 시 대화/선호도 저장 취소 정책
- 내비 ETA의 단위/갱신 주기, 검색 후보 ID 수명, 취소된 검색 결과 차단
- 차량 변경 감지의 출처 구분과 복원 핸들 수명
- 안전 정차 검증과 CarUxRestrictions/위험 구간/오디오 포커스 상태 전달 계약
- 화면·프로세스 수명주기, 서비스 소유자, 백그라운드 허용 범위와 복원 정책

새 계약 수정 전에는 변경 이유, A/B 영향, 호환성 및 마이그레이션을 문서/PR에 먼저 설명한다. B 담당 SDK 호출은 A에서 구현하지 않는다. 위 항목은 현재 선언만으로 안전성이 강제되었다는 의미가 아니다.
