# B5-2 사용자별 음악 앱 설정과 실제 음성 연결

2026-11-12. 기존 프로젝트/Gradle/SDK 선언과 A 영역/공통 contract를 유지했다. B5-1 이후 사용자가 기본 음악 앱을 사용자 설정으로 선택하기를 요청해 프로필별 선택을 추가했다. 모든 음악 앱의 제3자 제어를 보장하거나 뉴스/음성 차량 제어를 구현한 것은 아니다.

## 사용자 설정

- 설치된 공개 MediaBrowserService를 조회한 뒤 ‘기본 앱으로 저장’를 누른다. 저장과 연결은 분리되어 있으며 저장/프로필 전환/앱 복귀만으로 자동 연결·재생하지 않는다. 사용자가 ‘연결’을 눌러야 한다.
- `MediaAppPreferences`는 B 내부 profile ID -> 서비스 component ID만 버전/길이/개수 검증을 거쳐 noBackupFilesDir/profiles/media-apps.bin에 원자 저장한다. A DriverPreferences에 필드를 추가하지 않았다. 사용자 이름/토큰/로그인 정보/발화/오디오 URI를 저장하지 않는다.
- 프로필별 설정은 다른 사용자에게 상속하지 않는다. 기본 앱 해제는 해당 사용자만 지우고, 프로필 삭제 후 유효 사용자 목록으로 설정을 정리한다. 손상된 파일은 성공/미설정으로 바꿔 덮어쓰지 않는다.
- 기본 앱이 존재하면 그 앱의 연결만 사용한다. 미연결/미지원/연결 거부 시 다른 앱이나 로컬 파일로 자동 대체하지 않는다. 저장된 앱이 없거나 목록에서 보이지 않으면 설치/공개 서비스 제공 여부를 확인해야 한다.

## 실제 음성 통합

- `LiveVoiceIntegration`은 기본 꺼짐이다. 최신 P단/정지 신호, 선택 프로필, 실제 내비 모드, 준비된 기본 음악 앱 또는 선택한 로컬 파일이 있어야 사용자가 연결을 켤 수 있다. 연결만 켜서는 질문/청취를 시작하지 않는다.
- ‘음성 출발 확인’은 DriveMateSession.initialCheck, ‘음성 상태 다시 확인’은 conditionCheck만 호출한다. 질문·답변 분류·모드·스케줄은 A에 그대로 맡긴다. 별도 STT 루프/분류기/스케줄을 B에 만들지 않았다.
- 출발 질문 후 NORMAL 응답이면 A의 기존 모드 질문에서 ‘음악 틀어줘’를 받을 수 있다. 기본 앱에서는 기존 프로필의 장르/가수 검색어 또는 A의 취향 질문 답변이 서비스 검색 재생 요청으로 전달된다. 실제 음악 검색 지원/결과 정확도는 외부 앱에 의존한다.
- 기본 앱 없는 로컬 경로는 ‘로컬 파일 틀어줘’/‘선택한 파일 틀어줘’/‘테스트 음 틀어줘’의 정확한 로컬 별칭만 허용한다. 가수/곡/장르 요청을 임의 로컬 파일로 성공 처리하지 않는다. Next와 뉴스는 로컬 경로에서 UNSUPPORTED다.
- B `MediaPreemptingVoiceBackend`는 각 speak/listen 전에 MediaCommand.Stop의 성공을 기다린 뒤 기존 PleosVoiceBackend에 위임한다. 실패/수동 재생 소유권 불명/상태 불명 시 TTS·STT를 시작하지 않는다. A SerializedVoiceService의 TTS/STT 직렬화를 유지한다. voice.stop은 SDK 음성 정리만 하므로 정상 재생 직후 A의 음성 정리 호출이 음악까지 즉시 끄지 않는다.
- 실제 SDK가 제공하는 기존 STT_SERVICE/TTS_SERVICE 권한 및 ON_DEVICE 경로를 사용한다. 새 SDK 호출/권한/생성형 AI는 추가하지 않았다. 실제 응답 원문을 로그/파일에 저장하지 않는다.
- 실제 음성 graph에는 명시적 실제 미디어 포트만 주입한다. 가상 graph에 mediaOverride를 주입하거나 실제 graph에 기본 MockVoiceBackend를 사용하는 조립은 거부한다. 실제 음성의 차량 포트는 UNSUPPORTED이며 Fake 차량 성공을 실제로 표시하지 않는다. 실제 음성에는 읽기 전용 경로 포트를 제공한다. 음성 경유지 추가/경로 재개/목적지 변경은 UNSUPPORTED이며, 별도 UI의 기존 B3 변경 포트와 동의 검증은 유지한다.
- A 출발 스케줄의 due 이벤트가 연결 직후 마이크를 열지 않도록 B 소유자는 사용자 출발/상태 확인 버튼 전 실제 세션 tick을 보내지 않는다. 이후 일정은 A가 정한다. 배경 이동 시 enabled를 즉시 끄고 A 작업을 취소/정리한 뒤 graph를 재생성한다. 복귀 시 자동 음성/음악 재개는 없다.
- 프로필/시나리오/내비 모드 변경도 기존 graph의 A 작업과 음성을 close 후 재생성한다. 직접 미디어 조작과 로컬 파일 교체는 실제 음성 모드에서 차단한다. 재생 중단 버튼은 유지한다.

## 실제 테스트 순서

1. 프로필 선택과 차량 조회를 켜고 최신 P단/정지를 확인한다.
2. 외부 앱을 쓸 경우 설치된 음악 앱 조회 -> 기본 앱 저장 -> 연결. 해당 앱에서 로그인한다. 로컬 시험은 기본 앱을 해제한 뒤 테스트 음을 선택한다.
3. 실제 내비 모드를 켜고 별도 동의로 목적지 안내를 시작한다. 실제 음성 연결 켜기 -> 준비됐을 때 ‘음성 출발 확인’을 누른다.
4. TTS가 끝나고 LISTENING이 표시되면 상태를 답한다. 정상 응답 뒤 모드 질문에는 ‘음악 틀어줘’ 또는 로컬 시험의 ‘로컬 파일 틀어줘’를 말한다. 이전 모드를 묻더라도 로컬 시험은 명시적인 로컬 요청을 말한다.
5. 음악 중 ‘음성 상태 다시 확인’을 눌러 재생이 먼저 중단되고 질문하는지 확인한다. 자동 음악 재개는 없다. A의 모드 질문은 경로/세션별 한 번이므로 재시험은 실제 음성 연결을 껐다 켠다.
6. 마이크 입력이 없거나 시간 초과/SDK 실패면 정상 응답으로 표시하지 않는다. 서비스/호스트 마이크 설정은 별도 확인이 필요하다. 수동 발화 시험은 사용자가 직접 시작하며 이번 자동 계측에서는 마이크를 열지 않았다.

## 출발 확인 버튼 비활성: 기존 내비 경로 관측

음성 출발 버튼은 route가 필요하지만 기존 B3의 controller.route는 앱이 직접 설정하고 확인한 원본 목적지 소유권이 있을 때만 발행됐다. 배경 이동/재연결 시 그 소유권을 폐기하므로, 차량 내비에서 계속 안내 중이어도 음성 세션에는 route=null일 수 있었다. 이것을 안전 조건 완화나 임의 목적지 재요청으로 해결하지 않았다.

ObservedVoiceRoute는 SDK의 최신 RouteState(active/termsAccepted)와 유효한 Destination/양의 남은 시간을 모두 받았을 때만 음성 스케줄용 RouteProgress를 발행한다. 각 근거는 10초 이내여야 하며 종료/재탐색/경유지 변경/실패/연결 해제/사용자 변경 시 폐기한다. 새 목적지의 관측 ID는 기존 제어 소유권이나 동의 ID로 사용하지 않는다. 이미 사용 중인 실제 SDK 조회/콜백만 소비하며 새 SDK 호출을 만들지 않았다.

실제 음성 graph는 이 관측 전용 포트와 미지원 휴식 장소 검색 포트를 사용한다. 관측 포트의 목적지 설정/경유지 추가/재개는 동의가 있어도 UNSUPPORTED다. 기존 B3 UI 제어 포트의 원본 소유권/동의 검증 및 A 코드는 유지한다. 공통 contract 변경 없음. 경로 근거가 없으면 출발 확인은 계속 비활성이고 화면에 경로·남은 시간 미확인 이유를 표시한다.
