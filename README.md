# 쉼길

## 공모전 제출 안내 — 두리두리

- **팀명:** 두리두리
- **앱 이름:** 쉼길
- **앱 소개:** 운전자의 음성 응답과 현재 주행 경로를 바탕으로 컨디션을 재확인하고, 피로 시 휴식과 지원 가능한 주행 보조 기능을 안내하는 Pleos Connect 차량용 앱입니다.
- **제출 브랜치:** `feature/b-integration`. 기본 `main` 브랜치의 초기 코드와 구분해 주세요. 접수 메일에 기재한 최종 커밋을 기준으로 소스와 APK를 함께 확인할 수 있습니다.
- **Release APK:** [apk/두리두리_쉼길.release.apk](apk/두리두리_쉼길.release.apk)
- **APK 다운로드:** [파일 다운로드](https://github.com/wjddlsdnr/DriveMate-Pleos/raw/refs/heads/feature/b-integration/apk/%EB%91%90%EB%A6%AC%EB%91%90%EB%A6%AC_%EC%89%BC%EA%B8%B8.release.apk)
- **빌드/서명 정보:** [apk/BUILD_INFO.md](apk/BUILD_INFO.md), [SHA-256](apk/SHA256SUMS.txt)

### 실행 방법

1. Android Studio에서 Pleos Connect 에뮬레이터를 실행합니다. 일반 휴대전화가 아닌 AAOS/Pleos Connect 환경을 대상으로 합니다.
2. 저장소 루트의 터미널에서 아래 명령으로 제출 APK를 설치하고 실행합니다.

```powershell
adb install "apk/두리두리_쉼길.release.apk"
adb shell am start -n com.example.pleosconnect/.MainActivity
```

기존 Debug APK와 제출 Release APK는 서명이 다르므로 업데이트 설치가 거부될 수 있습니다. 기존 앱 데이터를 지우는 자동 제거는 하지 않으며, 별도 시험용 AVD 사용을 권장합니다.

3. 프로필을 등록/선택하고 기본 시뮬레이션 화면에서 출발 확인 및 상태 확인을 시험합니다. 가상 응답·가상 동의를 실제 운전자 판단이나 실제 차량 제어 성공으로 해석하지 않습니다.
4. 실제 SDK 시험은 사용자가 실제 내비 연결·차량 조회·음성 연결을 별도로 켭니다. 실제 음성은 연결을 켜기만 해서는 시작되지 않으며, 준비 후 ‘음성 출발 확인’을 눌러 시작합니다. 버튼 아래의 미충족 조건 안내를 확인합니다. 마이크 청취를 준비하지 않은 상태에서 전체 실제 SDK 계측을 일괄 실행하지 않습니다.

### 테스트 환경과 필요한 설정

- **에뮬레이터:** Pleos Connect v2.1.0, AVD `Pleos_Connect_v2.1.0`, Android API 34, x86_64.
- **화면 규격:** AVD 설정 기준 2560×1440, density 160. 차량 시스템 UI가 앱에 할당하는 영역은 전체 화면보다 작을 수 있습니다.
- **빌드 환경:** Gradle 9.6.0, AGP 9.5.1, Kotlin 2.2.10, compile/target SDK 37, min SDK 30. 실제 시험 기기의 API와 빌드 target SDK는 서로 다릅니다.
- **Pleos SDK:** SpeechToText 3.3.1, TextToSpeech 3.3.1, NaviHelper 3.0.5, Vehicle 2.3.2. SDK 의존성은 Gradle로 해석하며 제한 SDK 바이너리를 소스 저장소에 별도 업로드하지 않습니다.
- **실제 음성:** 호스트 마이크 입력과 Pleos STT/TTS 서비스가 사용 가능한 환경이 필요합니다. 실제 차량 조회는 해당 SDK 권한 및 속도 조회 권한이 필요합니다. 거부/미지원 상태를 성공으로 표시하지 않습니다.
- **개인정보/키:** API 키·중계 토큰·개인 프로필·서명 개인키·비밀번호는 APK 제출 자료나 Git에 포함하지 않습니다. 프로필은 앱 전용 로컬 저장소에 보관합니다.

### 제출 Release의 범위와 미검증 항목

제출 APK는 versionName `1.0`, versionCode `1`, 패키지 `com.example.pleosconnect`의 서명된 Release입니다. 빌드·서명·ZIP 정렬 검증과 단위 테스트 474개 실패 0을 확인했습니다. 서명된 Release APK 자체의 새 기기 설치·실행/전체 심사 시나리오는 아직 별도로 검증하지 않았습니다.

- Release에는 개발용 ‘테스트 음 선택’과 PC 로컬 중계 주변 검색이 포함되지 않습니다. Debug의 로컬 중계 시험 성공을 제출 Release의 검색 성공으로 표현하지 않습니다.
- 외부 음악 앱은 공개 연동/로그인/검색 지원 범위에 의존하며, 실제 음악·뉴스 전체 연동과 실제 차량 변경·복원은 미완료 또는 미검증입니다.
- 주변 검색의 앱 버튼→결과 표시 전체 흐름과 실제 발화→상태 판단→재생→질문 전 중단의 안정적인 전체 통합 검증도 남아 있습니다. 현재 관측한 한계와 재현 조건은 [최신 인수인계](docs/B_HANDOFF.md), [주변 검색 앱 연결](docs/NEARBY_APP_INTEGRATION.md)에 기록했습니다.
- 차량 설정/경로 변경과 복원에는 별도의 명시적 동의가 필요하며 조향·제동·주행 중 좌석 이동·자동 긴급 신고는 제공하지 않습니다.

아래 소개와 Phase 설명에는 과거 단계의 기록이 포함됩니다. 현재 제출 버전의 실행 방법/환경/APK 위치는 이 제출 안내와 해당 커밋의 소스를 우선 확인해 주세요.

서비스 이름을 DriveMate에서 쉼길로 변경했습니다. 저장소·패키지·내부 클래스 이름과 과거 검증 기록에는 기존 이름이 남아 있습니다.

현대자동차그룹 Pleos Connect 차량용 앱 공모전 프로젝트.

개발을 이어받는 경우 [B 인수인계 문서](docs/B_HANDOFF.md)부터 확인하세요. 구현/실제 검증/미검증을 구분하고 최신 음성 출발 버튼 이슈와 실행 순서를 정리했습니다.

## 소개
쉼길은 음성으로 운전자의 상태를 확인하고, 예상 주행 시간을 구간별로 나누어 주기적으로 컨디션을 재확인하는 적응형 운전 지원 앱입니다. 피로·졸음이 보고되면 휴식을 권고하고, 지원되는 차량 기능 및 내비게이션과 연계해 안전한 정차 장소 안내를 지원합니다.

기능 기준은 [최종 기획안 v2.0](docs/PROJECT_SPEC.md) 1~16장입니다.

현재 앱은 [B2 로컬 프로필과 선호도 저장](docs/B2_PROFILES.md)을 제공하며 기본 주행 체험은 [B1 시뮬레이션](docs/B1_INTEGRATION.md)입니다. 별도 선택으로 [실제 내비](docs/B3_NAVIGATION.md), [차량 조회](docs/B4_VEHICLE_READ.md), [직접 동의하는 설정 변경](docs/B4_VEHICLE_CONTROL.md)을 개발 검증할 수 있습니다. [사용자별 음악 앱 설정과 실제 음성 연결](docs/B5_VOICE_MEDIA.md)을 추가했으며 실제 로컬 재생 중단→TTS 완료를 확인했습니다. 사용자 발화 전체 흐름과 외부 음악 앱 재생, 자동 휴식 검색/환기 및 실제 차량 변경·복원 검증은 남아 있습니다. A/B 현황과 후속 순서는 [B 개발 계획](docs/B_DEVELOPMENT_PLAN.md)을 참고하세요. 아래 Phase 설명은 각 단계 당시 기록입니다.

개발자 A의 Phase 0·1 결과는 [프로젝트 분석 및 SDK 확인](docs/PHASE_0_1.md), [A/B 개발 경계와 공통 계약](docs/DEVELOPMENT_BOUNDARIES.md)에 정리했습니다. [Phase 2](docs/PHASE_2.md)에서는 음성 실행 제어, 실제 Pleos ON_DEVICE STT/TTS Adapter 및 명시적 Mock을 추가했습니다. [실제 Emulator 검증](docs/PHASE_2_EMULATOR.md)에서 TTS 완료·동시 청취 차단·취소 및 한국어 STT 최종 결과 수신을 확인했습니다. UI 연결은 아직 구현하지 않았습니다.

개발자 A의 [Phase 3](docs/PHASE_3.md)는 순수 Kotlin 응답 분류와 상태 관리입니다. 제한된 문장 사전·회복 재확인·정차 확인 경계를 구현했으며 UI·음성 대화 흐름과의 통합은 후속 단계입니다.

[Phase 4](docs/PHASE_4.md)는 주입 시계를 사용하는 구간별 확인 스케줄러입니다. ETA 재계산·중복 방지·질문 충돌 병합·경로 종료 취소를 구현했으며 실제 내비·TTS 호출은 연결하지 않았습니다.

[Phase 5](docs/PHASE_5.md)는 피로·졸음·무응답 대응 조정기입니다. 휴식 권고, 명시적 동의 후 차량 보조 요청, 후속 확인 예약과 콘텐츠 중단 요청을 구현하고 Fake로 검증했습니다. 실제 차량·콘텐츠 SDK 및 화면 통합과 휴식 장소 검색은 후속 단계입니다.

[Phase 6](docs/PHASE_6.md)는 B의 휴식 장소 검색 요청·후보 음성 안내·명시적 동의 후 경유지 추가 요청 흐름입니다. 경로 변경 시 오래된 검색·동의를 폐기하고 중복 변경을 막으며, 실제 POI/NaviHelper·화면 통합은 포함하지 않습니다.

[Phase 7](docs/PHASE_7.md)는 정상 운전 모드·음악 명령 해석과 선호도 제안/저장 요청입니다. 위험 상태 및 사용자 전환 시 일반 콘텐츠를 차단·중단하며, 실제 미디어·프로필 저장 구현과 말동무 대화는 포함하지 않습니다.

[Phase 8](docs/PHASE_8.md)은 Gleo 지원 범위 조사와 STT/TTS 기반 제한 말동무입니다. 최대 2회 응답의 고정 대화·위험/모드/사용자/백그라운드 취소·안전 음성 소유권 인계를 구현했으며, Gleo 자유 대화·외부 생성형 AI 및 실제 UI 통합은 포함하지 않습니다.

## 개발 환경

미디어 후속: [B5-1 로컬 오디오와 미디어 서비스 연결](docs/B5_MEDIA.md). 사용자가 고른 로컬 오디오의 실제 foreground 재생·포커스/백그라운드 중단과 공개 MediaBrowserService 요청 경계를 추가했다. 실제 에뮬레이터의 두 서비스는 검색되지만 연결/목록 조회가 완료되지 않았으며 음악 소리 출력·뉴스 제공자·실제 음성/안전 선점 연결은 미검증 또는 미구현이다. 가상 주행 시나리오는 실제 음악을 제어하지 않는다.

차량 제어 후속: [B4-2 직접 동의하는 설정 변경](docs/B4_VEHICLE_CONTROL.md). 정차 신호·원본·지원 범위·새 동의를 확인하는 개발용 공조 전원/창문 절대 위치값 제어이며 실제 변경/복원 검증은 남아 있습니다. 온도 제어·좌석 이동·주행 중 자동 환기는 제공하지 않습니다.

최신 차량 작업: [B4-1 실제 차량 상태 조회](docs/B4_VEHICLE_READ.md). 별도 버튼으로 읽기만 연결하며 공조·창문·좌석을 제어하지 않습니다. P단·속도 0만으로 안전 주차를 확정하지 않습니다.

외부 검색 개발 현황은 [B3 휴게소 데이터 어댑터](docs/B3_PLACE_DATA.md)를 참고하세요. PC에서 도로공사 전체 카탈로그를 검증하는 단계이며 앱 자동 검색은 미지원입니다. 키는 APK에 포함하지 않습니다.

최신 B 작업: [B3 실제 내비 연결](docs/B3_NAVIGATION.md). 사용자가 별도로 켜는 실제 내비 모드에 목적지 동의 화면을 추가했다. SDK 연결·상태·즐겨찾기 조회는 검증했으며 실제 경로 변경 검증과 안전 휴식 장소 데이터 연결은 남아 있다.

- Android Studio, Kotlin, Android Automotive OS (AAOS)
- Pleos Connect SDK, Emulator, Virtual Console
- STT/TTS: 음성 질문·응답
- NaviHelper: 목적지 및 경유지 연동 (지원 범위 확인 필요)
- HVAC/Window/Seat: 차량 기능 연동 (권한과 차량별 지원 확인 필요)

## 안전 원칙
주행 중 강제 좌석 이동, 차량 강제 정차, 무응답만으로 119 자동 신고는 구현하지 않습니다. 실제 차량 기능은 공식 API·권한 확인 후 연결합니다.

> 현재 저장소는 개발 초기 단계이며, 위 기능은 구현 완료를 뜻하지 않습니다.

[Phase 9](docs/PHASE_9.md)는 안전 정차 후 휴식 타이머·최소 체크포인트 복구·회복 재확인과 명시적 동의 후 경로 재개 요청입니다. Fake 기반 구성 요소이며 실제 UI/OS 알람/Emulator 통합은 포함하지 않습니다.

[Phase 10 A 통합 및 B 인수인계](docs/PHASE_10.md)는 DriveMateSession에서 상태 확인·안전 대응·휴식 안내·타이머·동의 후 재개를 연결합니다. 가상 시간/Fake 통합 검증이며 B UI·실제 차량/내비 연동과 Emulator 통합 검증은 별도입니다.
